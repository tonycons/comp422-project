The Greedy Raccoon

A raccoon leaves its den to eat every piece of food on a 100 m × 100 m map. Food loses calories every second it waits, and spoiled food is worth nothing (0 calories). Which order should it eat in? The straightforward Greedy picks the best-looking next meal each time. The clever Subset DP (an exact dynamic program) plans the whole route first and always finds the best one.

      How they scale as the map grows

      One map can be luck. Here both algorithms solve 20 random maps of every size (the same maps on every computer; 10 of them are timed). Subset DP pays for optimality with exponential planning time, Θ(n²·2ⁿ) vs. Greedy's Θ(n²), but Greedy's shortfall in calories grows with n and its chance of finding the best route falls to zero.

        How it works

        Scoring

        Each food type has a calorie value and a shelf life. Freshness drops in a straight line from 1 (fresh) to 0 (spoiled) over that shelf life, and eating an item at time t is worth

        score(t) = calories × max(0, 1 − t / shelf life) = calories − w·min(t, shelf life),   where w = calories / shelf life

        Spoiled food is worth 0, never less. So the total score is (all calories on the map) − Σ wi·min(ti, shelf lifei): maximizing calories means minimizing a weighted sum of arrival times in which each item stops counting once it has spoiled, a variant of the weighted Traveling Repairman problem. The raccoon walks 1 m/s in straight lines and eats instantly.

        Greedy · straightforward

        Standing where it is, the raccoon walks to the most attractive uneaten item, then repeats: the nearest-neighbor heuristic (Rosenkrantz, Stearns & Lewis 1977), ranked by Smith's ratio rule (calories lost per second of waiting ÷ seconds of walking) instead of distance. It never looks past the next meal, so it is fast but can be fooled.

        Time
        Θ(n²)
        Memory
        Θ(n)
        Optimal?
        No

        Subset DP · clever

        A table with one cell per (set of items, item eaten last), filled for small sets first: the exact dynamic program for the traveling repairman problem (Wu et al. 2004; Roberti & Mingozzi 2014). Because spoiled food stops losing calories, each cell keeps a short list of (time, calories lost) labels instead of one number (Tsitsiklis 1992) and drops the ones that can never win.

        Time
        O(n²·2ⁿ·F), F = the longest label list (small in practice)
        Memory
        O(n·2ⁿ·F), which is why the race stops at 16 items
        Optimal?
        Yes, always

        About this page

        Both algorithms are written in TypeScript and run in your browser; the algorithms are in demo/src/solutions/. Automated tests check Subset DP against an exhaustive search of every order on small maps, and check that both algorithms keep producing the same routes on a set of reference maps. Timings are wall-clock, averaged over repeated runs. A map is fully determined by its size and seed, so the same seed gives the same map on every computer.

        Pseudocode, running-time analysis, the correctness proof and full references are in our project report.
