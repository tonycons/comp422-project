The Greedy Raccoon

A raccoon leaves its den to eat every piece of food on a 100 m × 100 m map. Food loses calories every second it waits, and spoiled food is worth nothing (0 calories). Which order should it eat in? The straightforward Greedy picks the best-looking next meal each time. The clever Subset DP (an exact dynamic program) plans the whole route first and always finds the best one.

        How it works

        Scoring

        Each food type has a calorie value and a shelf life. Freshness drops in a straight line from 1 (fresh) to 0 (spoiled) over that shelf life, and eating an item at time t is worth

        score(t) = calories × max(0, 1 − t / shelf life) = calories − w·min(t, shelf life),   where w = calories / shelf life

        Spoiled food is worth 0, never less. So the total score is (all calories on the map) − Σ wi·min(ti, shelf lifei): maximizing calories means minimizing a weighted sum of arrival times in which each item stops counting once it has spoiled, a variant of the weighted Traveling Repairman problem. The raccoon walks 1 m/s in straight lines and eats instantly.

        Greedy · straightforward

        Standing where it is, the raccoon scores every uneaten item and walks to the most attractive one, then repeats: the nearest-neighbor heuristic for the TSP (Rosenkrantz, Stearns & Lewis 1977), ranked by attractiveness instead of distance. Attractiveness is Smith's ratio rule: calories lost per second of waiting ÷ seconds of walking to it. Food that would already be spoiled on arrival ranks below all fresh food (nearest first). It never looks more than one step ahead, so it is fast but can be fooled: eating a nearby donut first can let a far-away fish spoil.

        GREEDY-RACCOON(items, den, speed)
 1  here = den
 2  clock = 0
 3  remaining = all n items
 4  route = empty list
 5  while remaining is not empty
 6      best = NIL
 7      best_value = −∞
 8      for each item j in remaining
 9          travel = distance(here, j) / speed
10          value = ATTRACTIVENESS(j, travel, clock + travel)
11          if value > best_value
12              best = j
13              best_value = value
14              best_travel = travel
15      clock = clock + best_travel
16      here = position of best
17      remove best from remaining
18      append best to route
19  return route
        Time
        Θ(n²): the loop on line 5 runs n times and the loop on line 8 runs over the n, n−1, …, 1 remaining items, so lines 9–14 run n(n+1)/2 times.
        Memory
        Θ(n): the remaining list and the route.
        Optimal?
        No. In the charts above it misses the best route on almost every map with 10+ items.

        Subset DP · clever

        Subset DP fills the table that Held & Karp (1962) and Bellman (1962) wrote for the traveling salesman, and that Wu et al. (2004) and Roberti & Mingozzi (2014) use to solve the traveling repairman problem exactly. It has one cell per (set of items S, item j eaten last): the cheapest way to eat exactly S, ending at j. A cell only needs the cells for S − {j}, so filling small sets first gives every cell its answer, and the full set gives the best route. It shares work between all orders that visit the same set, instead of trying all n! orders one by one.

        The one change for spoiling food: what it costs to finish a route depends on the clock, so a cell keeps the few (time, loss) labels that no other label beats on both, as in the forward label-propagation DP of Tsitsiklis (1992) for repairman problems, which tracks both time and waiting time. If food never spoiled, each cell would hold exactly one label: the table of Wu et al.

        SUBSET-DP-RACCOON(items, den, speed)
 1  T[i][j] = travel time i → j;  T0[j] = den → j
 2  for each item j:  C[{j}][j] = { (T0[j], loss_j(T0[j])) }
 3  for each subset S, smallest first (|S| ≥ 2)
 4      for each item j in S            ▹ eaten last
 5          prev = S − {j};  cand = { }
 6          for each item i in prev     ▹ eaten just before j
 7              for each label (t, c) in C[prev][i]
 8                  t′ = t + T[i][j]
                    add (t′, c + loss_j(t′)) to cand
 9          C[S][j] = PARETO-FRONT(cand) ▹ drop dominated labels
10  best = cheapest label in any C[ALL][j]
11  follow back-pointers from best to rebuild the route
12  return route
        Time
        Θ(n²·2ⁿ) for the one-value table (Wu et al. 2004): line 3 runs over 2ⁿ sets and lines 4 and 6 over n items each. With labels it is O(n²·2ⁿ·F), where F is the longest label list (a small number on these maps, shown in the results table; the fit above treats it as a constant).
        Memory
        Θ(n·2ⁿ) cells (×F labels), which is why the race stops at 16 items.
        Optimal?
        Yes, always: every possible order is covered by some path through the table. The tests also check it against the Python version route for route.

        About this page

        The algorithms are a TypeScript port of the group's Python implementation (ai-claude/raccoon/). Automated tests check that both versions produce identical routes. Timings are measured in your browser (wall-clock, averaged over repeated runs), so they differ from the Python benchmark numbers. Maps here use a different random number generator than Python, so a seed on this page is not the same map as that seed in python main.py demo.
